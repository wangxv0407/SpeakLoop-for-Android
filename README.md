# SpeakLoop for Android

把「骑车通勤听播客学短语」这件事做成一个**装在手机上的独立 App**，不需要电脑、不需要服务端。

## 和 Web 版的根本区别

| | Web 版 | 这个 App |
|---|---|---|
| 谁来合成语音 | 微软 Edge TTS，**必须跑在服务端** | 手机系统自带 TTS，**完全离线** |
| 要不要一台电脑常开 | 要 | **不要** |
| 要不要联网 | 每次生成音频都要 | 只有「AI 补全例句」需要 |
| 数据存在哪 | 电脑上的 `data/app.db` | 手机 App 私有目录里的 SQLite |

为什么 Web 版非要有服务端：微软 TTS 的握手要 `Origin: chrome-extension://...` 和特定 `User-Agent`，
这两个头浏览器强制管控、页面脚本改不了，所以浏览器直连必然 403。

而安卓自带 `TextToSpeech` 引擎就能读英文，不需要冒充、不需要联网、也不涉及任何灰色地带的接口。
代价是音色取决于手机自带的 TTS 引擎（通常是 Google 的英文音色），不是微软那套神经语音。

## 怎么拿到 APK

不需要装 Android Studio。用 GitHub Actions 在云端编译：

```sh
# 1. 在 GitHub 上新建一个空仓库（不要勾选 README）

# 2. 把本目录推上去
cd speakloop-android
git init
git add .
git commit -m "SpeakLoop Android v1"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

推上去后 GitHub 会自动开始构建（`.github/workflows/build.yml`）：

1. 打开仓库页面 → 顶部 **Actions** 标签
2. 等那条 `Build APK` 变成绿色对勾（第一次大概 3~5 分钟）
3. 点进去 → 页面底部 **Artifacts** → 下载 `speakloop-debug-apk.zip`
4. 解压得到 `app-debug.apk`，传到手机安装

装的时候系统会提示「未知来源」，允许即可。这是自己编译的 debug 包，用 Android 的调试证书签过名，可以正常安装。

> 想重新构建：Actions 页面 → 左侧 `Build APK` → 右侧 `Run workflow`。

### 关于签名（v1.2 之后请务必了解）

v1.2 之前的三个包，签名证书**三个都不一样**。原因是 GitHub Actions 每次跑在全新机器上，
AGP 发现没有 `~/.android/debug.keystore` 就现场生成一把新的，于是：

- v1.1 装不到 v1 上（系统报「应用未安装 / 签名不一致」）
- 只能先卸载再装，而短语存在 App 私有目录里，**卸载即全部丢失**

v1.2 起把一把固定的 debug keystore 放进仓库（`keystore/debug.keystore`，口令就是公开的 `android`），
所有构建共用同一把钥匙。所以：

- **最后一次需要卸载重装**：因为新包签名和 v1.2 之前所有包都不同
- 从 v1.2 往后的版本，都能直接在旧版上覆盖安装，短语不会丢

> 为什么敢把 keystore 传到公开仓库：这只是自用 debug 包，Android 的 debug 密钥本来就是
> 固定口令 `android`、不做保密的设计，泄露它的唯一后果是别人能用同一把钥匙签一个 App —— 
> 但别人签的 App 装不到你手机上（要么你主动装，要么需要设备权限）。真要正式发布再换你自己的正式证书。

### 设置 AI（v1.2 起可以自检）

1. 点底栏 **设置 → AI 补全**
2. **Base URL** 只填到 `/v1`，例如 `https://api.agnes-ai.cn/v1`。
   就算你不小心粘了整条 `.../v1/chat/completions`，App 也会自动剥掉，不用手改。
3. **API Key** 填 `sk-` 开头那串
4. **模型** 填 `agnes-2.5-flash`
5. 点 **🔍 测试连接**，几秒后下面会出结果：
   - 绿色「✅ 连接成功」并显示请求地址、模型、用时、模型回复 → 三项都没问题
   - 红色「❌ …」会直接告诉你是 `model_not_found`（模型名不对）、401（密钥无效）还是地址不存在
6. 确认绿色之后再点「保存」

## 怎么用

底栏四个 tab：**短语 / 统计 / 复习 / 设置**。

### 短语

1. 首次打开会自动塞 2 条示例短语
2. 顶部是**今日进度卡**：今天练了几条 / 每日目标，中间是完成度圆环，下面一行是本周新增、连续天数、总条数
3. 点右上角 **＋** 添加，勾上「用 AI 补全」会自动生成中文释义、2 句例句、4 句情景对话，存完直接跳进详情页
4. 下面按日期分组：今天 / 昨天 / 本周更早 / 更早，点分组标题可以收起，往期默认收起
5. 点一条 → **详情页**（独立页面）：
   - **▶ 朗读全部**：短语慢读一遍再正常读一遍，然后一句句往下读例句和对话，当前句变蓝，可随时停
   - **🎤 跟读**：调起系统语音输入界面，说完自动回来逐词对比
   - **🎤 录一遍 / 听录音**：录下自己的发音回放对比（只留最近一遍）
   - **长按**例句或对话：可以改文字、改中文、或删掉这一句
   - 右上角垃圾桶删掉整条
6. 长按列表里的一条 = 删除

### 复习

1. 顶部那个日期胶囊默认是「今天」，点它可选**任意一天**（只列有短语的那些天）
2. 默认范围 = 今天新加的 + **从没练过的旧词**（可在设置里关掉），一轮最多 15 条
3. 点大按钮开始。读的时候当前句变蓝；读完进留白，绿色圆环**从 4 倒数到 1**，倒数完自动读下一句
4. 播完就停，**不自动循环**（循环开关在复习页底部和设置里）
5. 息屏照读。耳机线控单击暂停、双击下一句，通知栏也有 暂停 / 下一句 / 停止
6. 底部三个小开关：只读短语（跳过例句和对话）、循环、语速

### 统计

- **打卡率圆环**：这个月已过去的天数里，有几天真的练了
- **练习记录热力图**：最近 91 天每天练了几条，颜色越深越多
- **练得最多**：本月 top 3

### 设置

- 复习：每天练几条（3/5/8）、一轮最多几条（10/15/25/不限）、要不要补上从没练过的
- 播放：语速 ×0.7~×1.3、例句后留白（4 秒跟读 / 0.5 秒只听）、循环
- 外观：跟随系统 / 浅色 / 深色
- AI 补全：Base URL、API Key、模型，带「测试连接」

> 两个「连续天数」口径不同，别搞混：
> 短语页那个是按**加短语**的日期算（我这几天有没有在积累），
> 统计页那个是按**练习**的日期算（我这几天有没有在练）。

## 有哪些功能

- 短语库：新增 / 删除 / 按日期分组折叠 / 长按删除
- 今日进度卡：每日目标进度圆环 + 本周新增 + 连续天数 + 总数
- 语音输入短语：添加时点「说一遍」，调系统语音输入界面，不用手打
- AI 补全释义、例句、情景对话；老数据可一键补中文
- 例句和情景对话可长按逐句修改或删除
- 复习：按天组队（可补旧词）、留白倒数、只读短语、循环、语速可调、后台息屏播放
- 耳机线控 / 蓝牙按键 / 通知栏控制
- 详情页：朗读全部、跟读逐词对比、录音回放
  - 跟读：红字加删除线 = 漏读（原文有、你没说），黄字 = 多读（你说了原文没有的），底部命中率 ≥80% 绿、≥50% 黄、否则红
- 统计：打卡率、91 天热力图、本月练得最多
- 浅色 / 深色 / 跟随系统三套主题

## v1 还没有

- **导出音频文件**（现在是实时朗读，不落地成 mp3；要导出得做 WAV/PCM 拼接）
- 手动编辑已保存的短语（只能删了重加）
- 跟读录音留存（只做识别对比，不保存你的录音文件）

## 关于语音识别（v1.5 起跟读换了路子）

v1.1~v1.4 的跟读用的是 App 内的 `SpeechRecognizer`，在华为这类**没有 Google 语音服务**的机型上基本用不了：
`isRecognitionAvailable()` 可能返回 false，也可能返回 true 但根本不回调，表现出来就是「给了麦克风权限之后什么也没发生」。

v1.5 改成**先看手机上有没有系统语音输入界面**（`RecognizerIntent`，就是输入法里那个小话筒）：

1. 有 → 直接把界面拉起来，靠识别器 App 自己录音，**我们不需要申请麦克风权限**，华为也照用
2. 没有 → 才退回 App 内的 `SpeechRecognizer` + 申请录音权限
3. 两条都不通 → 在结果区直接打出诊断：「系统语音输入界面：没有 / 应用内识别服务：没有」，
   这时候是手机真的缺语音识别服务，去「设置 → 应用 → 默认应用 → 语音输入」装一个或启用一个

├── PageSettings.kt      第四屏：复习 / 播放 / 外观 / AI

├── Db.kt                SQLite：phrase + play_log 两张表
├── VoiceMemo.kt         跟读录音（每条短语一个 m4a，覆盖式保存）

也没有 androidx.media（耳机线控用的是系统自带的 `MediaSession`）。

## 数据是怎么记的

`phrase` 表一条短语一行，`play_log` 表记「哪一天练了哪条、几次」。

v1.5 及以前是在**按下开始的那一刻**给全表 `play_count +1`，一句还没读就全加了，
所以列表上那个次数其实是「复习过多少轮」，按次数排序也排序了个寂寞。v1.6 改成：
**真的读到某条短语的第一个字时，才给那一条 +1**，同时往 `play_log` 写一笔今天的记录。

`play_log` 有两个日期概念，别混：

- 短语的 `created_at`：这条**哪天加的**，决定它出现在哪个日期分组、哪个复习范围里
- `play_log.day`：这条**哪天练的**，永远是「今天」，热力图和打卡率都按它算

所以你今晚补练 10 月 20 日加的词，热力图上亮的是**今天**那个格子。
